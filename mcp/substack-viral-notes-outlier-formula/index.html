Option B — Python: Compute Weighted Viral Score & Outlier Multiplier Locally

score_substack_outliers.py 
import requests

handle = "gurwinder"
profile = requests.get(f"https://substack.com/api/v1/user/{handle}/public_profile", timeout=20).json()
feed = requests.get(
    f"https://substack.com/api/v1/reader/feed/profile/{profile['id']}?types[]=note&limit=50",
    timeout=20,
).json()

notes = []
for item in feed.get("items", []):
    c = item.get("comment") or {}
    if not c or c.get("ancestor_path"):
        continue  # skip thread replies
    likes = c.get("reaction_count") or 0
    replies = c.get("children_count") or 0
    restacks = c.get("restacks") or 0
    score = likes + 3 * replies + 5 * restacks
    if score > 0:
        notes.append({"id": c.get("id"), "score": score, "body": (c.get("body") or "")[:90]})

baseline = sum(n["score"] for n in notes) / max(len(notes), 1)
for n in sorted(notes, key=lambda x: x["score"], reverse=True)[:5]:
    mult = round(n["score"] / baseline, 1)
    print(f"{mult}x (score={n['score']}): {n['body']!r}")

5. Frequently Asked Questions

How is the Substack Notes Viral Score and Outlier Multiplier calculated?

Each standalone Note is scored as likes + 3 * comments + 5 * restacks so restacks carry the highest weight for cross-feed distribution. outlierMultiplier divides that score by the creator's own baseline average positive score, flagging Notes with outlierMultiplier >= 2.0 and viralScore >= 25.

Why normalize Substack Note outliers per creator instead of using raw like counts?

Raw like thresholds conflate audience size with hook quality. In cloud run UxzOBHdfAQTnLqZMl, @gurwinder (85K+ subscribers) averaged a 782 viral score while @dan (5.3K+ subscribers) averaged 75; per-creator normalization isolates genuine 2x–7.2x breakout formats regardless of subscriber count.
